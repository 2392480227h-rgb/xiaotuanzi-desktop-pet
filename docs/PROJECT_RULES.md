# 项目规则

## 1. 角色一致性

小团子是项目核心角色。标准脸型：

`૮₍ ˃ ⤙ ˂ ₎ა`

任何视觉迭代都必须以既有设定为基础，不得为了方便开发随意替换脸型、眼睛、嘴部字符或角色核心识别元素。

## 2. 先理解再实现

复杂功能开始前，先明确：

- 用户体验目标
- 数据结构
- 状态变化
- 模块边界
- 输入与输出
- 异常情况

不能因为 AI 能直接生成代码，就跳过设计。

## 3. 小步可运行

每次改动尽量保持项目可运行。

推荐循环：

理解 → 设计 → 实现 → 运行 → 检查 → 修正 → 提交

## 4. 学习模式

这个项目同时承担编程学习任务。

AI 可以帮助解释、检查和实现，但不能把用户应该掌握的知识全部隐藏起来。

重要代码必须能够解释：

- 它做什么
- 为什么这样写
- 修改它会产生什么影响

## 5. 质量标准

项目不是一次性演示。

目标是：

- 功能完整
- 结构清楚
- 交互自然
- 视觉统一
- 代码可维护
- 文档清晰
- 最终具备真正作品的完成度

## 6. Git 规则

提交信息尽量表达实际变化，例如：

- feat: add character interaction
- fix: correct pet state transition
- refactor: split state management
- docs: update roadmap

不要使用无意义的 commit message。

## 7. 技术克制

没有实际需求时不添加依赖。

第一阶段优先原生 HTML/CSS/JavaScript/SVG。
